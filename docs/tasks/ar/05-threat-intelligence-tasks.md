# مهام المرحلة 5 — Threat Intelligence (Hash-based)

## حساب الـHash
- [ ] كتابة دالة Kotlin لحساب SHA-256 لملف APK لتطبيق معيّن (عبر `sourceDir`).
- [ ] التعامل مع الأخطاء (ملفات كبيرة، صلاحيات قراءة محدودة على بعض الأجهزة).
- [ ] تخزين الـHash المحسوب مؤقتًا (Cache) لتفادي إعادة الحساب في كل فحص.

## التكامل مع مصدر خارجي
- [ ] اختيار مزود Threat Intelligence (مثل VirusTotal API - Hash lookup endpoint فقط).
- [ ] تنفيذ استدعاء HTTP للتحقق من الـHash (بدون رفع أي ملف).
- [ ] معالجة الاستجابات: Known-clean / Known-malicious / Unknown.
- [ ] إدارة مفاتيح API بشكل آمن (عدم تخزينها كنص صريح في الكود).
- [ ] وضع حد أقصى لعدد الاستدعاءات (Rate limiting) لتفادي تجاوز حصة الـAPI.

## قاعدة بيانات محلية مبدئية
- [ ] تصميم جدول محلي (SQLite) لـ`malware_hashes` و `suspicious_packages`.
- [ ] كتابة دالة للتحقق أولًا من القاعدة المحلية قبل استدعاء الـAPI الخارجي.
- [ ] آلية تحديث القائمة المحلية يدويًا في هذه المرحلة (التحديث التلقائي من Backend يأتي في المرحلة 7).

## الدمج مع Risk Engine
- [ ] إضافة إشارة جديدة `ThreatIntelSignal(hash, status)` إلى RiskEngine.
- [ ] تحديد نقاط إضافية عند نتيجة "Known malicious" (تتوافق مع +100 المتفق عليها).
- [ ] اختبار السيناريو الكامل: تطبيق بـhash معروف كخبيث (بيانات وهمية للاختبار) يظهر بخطورة CRITICAL.

## معيار إنهاء المرحلة
- [ ] فحص تطبيق حقيقي، حساب hash له، التحقق منه عبر API خارجي، ودمج النتيجة في التقرير النهائي بنجاح.
